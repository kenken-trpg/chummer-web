- **冷えたカタログに同時到着したリクエストが、同じビルドを人数分走らせていたのを直した。** `lru_cache` には「いま計算している呼び出し元を待つ」仕組みがなく、最初の呼び出しが返る前に来たリクエストにはもう一度関数を走らせます。カタログのビルドは XML 24 本の再パースなので、vCPU 1 個のうえでは互いを食い合います（起動時の競合は `/api/ready` で塞いでありましたが、カスタムデータの overlay key では今も起こり得ました）。overlay key ごとの再入可能ロックを `catalog()` の手前に置き、`/api/catalog` のシリアライズにも同じ扱いをしました。
