# 使ってはいけない訳語

`docs/translation-glossary.md` が正典ですが、正典との照合を機械で全自動にはできません。
日本語の文だけを見て「どの英語用語の訳か」は復元できないためです。そこで、**過去に実際に
混入した誤りだけ**をここに記録し、`scripts/check_ja_terms.py` が `frontend/lib/i18n/locales/ja/`
と利用マニュアル（`frontend/public/manual/`）を走査して再発を落とします。マニュアルは画面の
語で画面を説明するものなので、下の表をすべて当てます（docs は「docs にも当てる語」だけ）。

新しい表記のずれを直したら、ここに 1 行足してください。それ以降その語は二度と入りません。

- `誤` — 禁止する表記。部分一致で探します。
- `正` — 正典の訳語。
- `典拠` — `docs/translation-glossary.md` の行。
- `許容` — その語を含んでいても正しい語（カンマ区切り）。空欄なら例外なし。

## docs にも当てる語

上の表は画面の文言（`frontend/lib/i18n/locales/ja/`）に当てます。Markdown の docs には、
このうち**ルール用語の誤訳としてしか使われない語**だけを当てます。`判定`（〜かを判定する）や
`値段` は docs では普通の日本語で、上の表をそのまま当てると誤検知ばかりになるためです。

docs ではバッククォート（`` `物理リミット` ``）の中は引用として扱い、検査しません。古い語を例に挙げるときや、
コード・ファイル上の名前を書くときはバッククォートで囲んでください。対象は `CHANGELOG.md`（リリース済みの記録）と、
この一覧・用語集を除く、リポジトリの Markdown です。

## 英語の画面文言に当てる語

`frontend/lib/i18n/locales/en/` には、用語集の英語の列（Chummer の英語）と違う呼び方だけを当てます。
英文では `power points` のように小文字で書くのが普通なので、大文字・小文字は区別せずに探し、
大文字・小文字の揺れそのものは問いません。キー名（`"res.fadeResist":`）と差し込み（`{fade}`）は検査せず、文言だけを見ます。

| 誤 | 正 | 典拠 | 許容 | 直した経緯 |
| --- | --- | --- | --- | --- |
| physical monitor | Physical Track | Physical Track (443) |  | ヘルプの CM の式と能力値の説明に 4 箇所 |
| stun monitor | Stun Track | Stun Track (556) |  | 同上。A.I. のコアダメージトラックのヘルプにも |
| core monitor | Core Damage Track | Core Damage Track (637) |  | A.I. のヘルプ（#608 で入れた） |
| fade | Fading | Fading (243) | fades | 複合体・スプライト・シートに 7 箇所。`fades`（徐々に消える）は普通の動詞 |
