# ライフモジュール（試験対応）

技能上限・超過分移し替え・キャリア成長の仕様は、
[詳細設計](plans/life-module-skill-overflow-design.md)を参照してください。

ライフモジュール方式は Run Faster（RF pp.65–86）の経歴を積み上げて作成する方式です。
固定データの325候補の選択・計算・ブラウザ保存・JSON バックアップに対応しています。
.chum5 の書き出しと、このアプリが書き出したファイルの再読み込みもできます。
能力値上限の精算は未対応です。知識技能超過の配分は本アプリの独自ルールとして対応しています。Chummer 本体が保存したファイルとの互換性については、
下記の対応範囲と「.chum5 入出力」を参照してください。

## 操作

1. 作成方式タブで「ライフモジュール」を選びます。使用ルールブックに RF などを追加するか、
   Chummer の Life Modules プリセットを選択します。
2. Nationality（国籍）・Formative Years（幼少期）・Teen Years（少年少女期）・
   Further Education（追加教育）・Real Life（実生活）の経歴を選びます。段階の名前も
   Run Faster 由来のデータなので、日本語設定でも英語で表示します。
   Further Education と Real Life は異なる経歴を選べます。同じ経歴は1回だけで、
   Corporate の Hacker/Decker と Security Rigger のように同じ親を持つ派生版も、
   親ごとにいずれか1つだけ取得できます。進学しない場合は
   Skipped Further Education を選びます。
   「経歴を検索」で名前・派生元・説明・出典を絞り込めます。検索は使用ルールブックの
   候補内で行い、選択済みの経歴と追加選択欄は検索中も表示します。
   各段階には選択済み・未選択を表示し、選択した経歴は個別の枠で表示します。
   「経歴の説明」を開くと、元データにある場合は英語の説明を読めます。
   追加選択欄は画面幅に応じて列数を調整します。
   候補はプルダウンではなく一覧に表示し、名前・派生元・費用・出典・前提条件を比較できます。
   候補を選ぶと説明・追加資金・資質の無料ポイント・追加選択の件数を詳細欄に表示します。
   「この経歴を追加」を押すまでは保存内容を変更しません。
   条件を満たさない候補や未対応の候補も詳細を確認できますが、追加はできません。
3. 経歴が求める能力値・技能・知識などの選択肢を指定します。知識名の自由記入にも対応します。
   メタタイプ・資質の前提条件は候補に英語で表示します。条件を満たさない候補は選択できません。
   選択後に条件を満たさなくなった経歴には警告を表示します。
   資質に追加指定が必要な場合は、経歴内の資質名付き入力欄に記入します。Codeslinger は行動を選択します。
   Records on File のように取得ごとに対象を持つ資質は、経歴ごとに別の取得として並び、それぞれの指定を保ちます。
   それ以外の資質で経歴と手動取得の指定が食い違う場合は、競合を作成エラーとして表示します。
   Incompetent は技能グループを候補から選択します。経歴が明示する資質のレベル数も付与に反映します。
   知識カテゴリーが選択式の場合は候補から選び、専門化の内容が未指定の場合は入力します。
4. 能力値・技能タブの入力は手動購入分です。経歴による技能付与は上限7（知識技能9）で判定し、
   個別技能の超過分は同じ関連能力値の技能へ割り振ります。受け手の空きがなければ残りは失効します。
   知識・言語技能の超過分は、別の知識・言語技能に配分できます。これは本アプリの独自ルールです。
   明示した設定上限があればそれを使います。手動購入は無償付与後の値から価格を計算します。
5. 作成チェックで未選択の人生段階・追加選択・カルマ不足などを確認します。
   バックアップには JSON 書き出しを使います。
   保存データにカタログにない経歴が含まれる場合は、不明な経歴として ID を表示します。
   作成中なら画面から削除でき、後続の経歴の追加選択は維持されます。

標準の作成カルマは 750 です。設定の `karma_chargen_pool` に明示した値があれば優先します。
経歴の費用と、メタタイプ・追加能力値・追加技能などの費用を同じプールから支払います。

### 知識・言語技能の上限超過

[Run Faster p.66](https://thyamath.fr/Shadowrun/SR5/Shadowrun_5E_Run_Faster.pdf) は知識技能の上限を9と定めますが、知識技能の超過分の再配分方法は指定していません。
本アプリでは作成中に限り、上限を超えた経歴の付与レベルを別の知識・言語技能へ配分できます。
同じ技能自身と母語には配分できず、受け手も上限9（設定で変更した場合はその値）までです。
行き先はカタログの技能名から選ぶか、名前と区分を入力して追加できます。経歴ごとに未配分・過配分・重複・無効な区分を検出し、解消するまでキャリアへ進めません。
配分は無償付与として扱い、知識技能ポイントやカルマ購入には数えません。
経歴の変更で元の付与が変わった配分はエラーとして保持するため、画面から修正できます。

## 対応範囲

上流と同じコミットに固定した `lifemodules.xml` を取得します。親モジュールの費用・効果を
派生版が引き継ぎ、派生版も含めた 325 候補を表示します。対応する効果だけで構成された候補を選択できます。
能力値・能動技能・技能グループ・知識技能のレベル付与（候補制限付き技能選択を含む）、母語付与、選択肢、
追加選択を要しない資質の付与、選択式の資質、資質グループのレベル付与（同一グループは最高レベルを採用）、レベル数付きの資質付与と同じ資質の手動取得の併用（付与分は無料、手動分だけカルマ。合計で資質の上限まで）、資質の無料ポイント、追加資金、固定の技能専門化、固定値のコンタクト付与に対応しています。Real Life の非グループ技能と知識技能は上限超過を割り振れます。作成結果をキャリア開始時に固定し、技能・知識技能のカルマ成長と最後の成長の取り消しに対応します。

未対応のものも一覧に残し、選択不可にします。JSON などから直接指定された場合も
作成エラーにして、効果の一部だけを適用することを防ぎます。主な未対応処理は以下です。

- 定義のない資質グループの段階的付与（`addqualities` 内に入れ子になった既知の `qualitylevel` は対応済み）
- 能力値の上限超過の精算。
- 前提条件に未対応の条件を含む経歴
- 資質の文章指定・マトリックス行動選択・技能グループ指定・資質選択・資質の段階選択・候補制限付き技能選択以外の追加選択や、データから効果を確定できない経歴
- Chummer 本体が保存したライフモジュールのキャラクターから、経歴と選択を復元すること。
  保存された値を保つキャリアスナップショットとして読み込みます（下の「.chum5 入出力」）。

ライフモジュール名・派生元名・人生段階名・選択肢など、Run Faster 由来のデータは日本語設定でも原文の英語で表示します。
パネルの文言（見出し・ボタン・費用の集計・注意書き）も、データに合わせて日本語設定で英語にしています（#565）。
例外は技能の上限と超過分の移し替えの欄で、こちらは選択中の言語で表示します。画面の「?」の説明も、隣の文言と同じ言語で出します。

## .chum5 入出力

書き出しと、このアプリが書き出したファイルの読み込みに対応しています。Chummer 本体が
保存したライフモジュールのキャラクターは、経歴を復元せず、キャリアのスナップショットとして
読み込みます（#563。下の「Chummer 本体が保存したファイル」）。

Chummer は経歴を独自の資質種別として保存します（`Chummer/Backend/Uniques/Quality.cs`、
`<qualitytype>LifeModule</qualitytype>` と、この種別だけに付く `<stage>`）。付与された
能力値や技能はキャラクター本体に焼き込まれ、**どの選択肢を選んだかは残りません**。
325 経歴のうち 219 が 1 つ以上の選択を持つため、保存された結果から選択を逆算することは
できません。

このアプリは経歴のID・選択の答え・超過配分・手動購入値を保存し、付与内容は
計算のたびにエンジンが導出します。そのため書き出しでは

- 経歴を Chummer と同じ形（`qualitytype` / `qualitysource` / `stage`）で `<qualities>` に書き、
  Chummer が開けるようにします
- 旧形式では選択の答えを `<lifemodulechoices>` に並べました。新形式では取得順・配分・
  購入入力・キャリア履歴を `<lifemoduleskillstate version="2">` に保存します。
  Chummer はこの拡張を無視し、標準の技能欄には解決済みの結果を書きます。

選択キーは経歴を**並び順**（エンジンの `occurrence`）で指し、読み込みも文書順で復元します。
経歴 1 つを落とすと以降の選択が別の経歴にずれるため、データにない経歴が 1 つでもあれば
読み込みを中止します。新拡張の重複・未知の要素と標準技能欄の編集も検出して読み込みを拒否します。
旧 `<lifemodulechoices>` も新拡張も無いファイルは、Chummer 本体が保存したものとして下のとおり扱います。

新形式は技能・知識技能の標準欄に解決結果を書き出します。属性・資質・コンタクトなども含めた
Chummer本体での実動作互換は確認していません。ライフモジュール状態を完全に復元する用途では
このアプリのJSONバックアップを使用してください。

### Chummer 本体が保存したファイル

経歴の資質（`qualitytype` が `LifeModule`）はあるのに選択の答えが無いファイルは、
Chummer 本体で開いて再保存したものです。経歴を捨てて付与をやり直すと値が変わるので、
保存された値をそのまま保つキャリアのスナップショットとして読み込みます
（`chummer_import/__init__.py` の `external_module_snapshot`）。

- 作成方式は Karma、キャリア中にし、読み込んだ時点の値をキャリアの基準にします。
  以後の成長は、この基準からの差だけカルマを払います。
- 経歴は `life_module_archive` に名前の記録として残し、`life_modules` は空にします。
  記録は書き出しにも載りますが、付与には使いません（読み直しても付与が二重になりません）。
- 残りのカルマ・資金はファイルの値に合わせます。
- 「経歴の選択と超過分の移し替えは復元できない」という警告（`engine.life.chum5Snapshot`）を出します。

作成方式が LifeModule なのに経歴の資質も選択の答えも無いファイルは、
何を復元すればよいか分からないので拒否します（`engine.life.chum5Unsupported`）。
検証には `docs/fixtures/EX_chummer-life-module-skill-overflow.chum5` を使っています
（`tests/test_life_module_desktop_compatibility.py`）。


例外が 1 つあります。作成エラーの文中のモジュール名だけは、カタログの訳語表を引きます。
表に載っていない名前は英語のまま出ますが、`History`・`Law`・`Medicine` など 11 件は
知識技能などと同じ名前のため、エラー文では訳語（歴史学・法律・医学…）で出ます。

### 元データの参照表記

固定データでは、資質名に次の表記差があります。これらだけを明示的に読み替え、
一致しない名前の類似検索や、不明な段階の自動選択は行いません。

| 経歴データの参照 | 適用する資質・追加指定 |
| --- | --- |
| Silence Is Golden | Silence is Golden |
| Too Pretty to Hit | Too Pretty To Hit |
| Phobia (Mild, Common) | Phobia (Common, Mild)。対象は利用者が指定 |
| Home Ground (You Know A Guy) | Home Ground、追加指定は You Know A Guy |
| SINner: National | SINner (National)。追加指定は利用者が入力 |

`addquality/options/quality` の選択式付与も読み取ります。現在の対応候補は325件／325件です。
Corp College Student は [Street Lethal p.128](https://www.thyamath.fr/Shadowrun/SR5/Shadowrun_5E_Street_Lethal.pdf) の5 Karmaという指定をカタログと照合し、
このモジュールIDに限って Day Job (10 hrs) に解決します。Etiquette の Academic 専門化、
Academic / Professional の知識カテゴリー選択も反映します。他の無指定の Day Job は読み替えません。
技能内の固定専門化・自由入力の専門化は無償付与し、知識技能の専門化にも対応します。
Azanian Confederation は、単数形の `option` から候補を読み取ります。
親モジュールID `baa9a6cc-2fb8-49d3-b503-d1f74bd0d915` に限り、言語名の候補が並ぶ
2つの付与の欠落カテゴリーを `Language` と補完します。これは固定XMLの候補名と値を根拠にした
データ解釈であり、Better Than Bad p.162 の国籍表を直接確認した修正ではありません。
値0の母語と値1の追加言語に反映し、言語候補外の入力は拒否します。
Zulu Nation の都市は New Hlobane の候補表示に加えて任意の都市名を入力できます。
`[City]` のようなプレースホルダーそのものは入力値として認めません。
既存の同地域 SINless の保存にも同じ補正を適用し、選択キーは維持します。
以前の自由入力が現在の言語候補に含まれない場合は、選び直すまで作成エラーになります。

Warm Body が求める `Corporate Pariah` には段階の指定がありません。
[Street Lethal p.127](https://www.thyamath.fr/Shadowrun/SR5/Shadowrun_5E_Street_Lethal.pdf) は I / II の2段階を載せており、
同書 p.129 のモジュール記載にも固定XMLにも、どちらかを示す記述はありません。
そこで段階を自動決定せず、`Corporate Pariah I / Corporate Pariah II` の候補として利用者が選びます。
段階を選ぶと、その資質の文章指定（対象の企業名）を別の入力欄で指定します。
補正はこのモジュールID `14dfb0c8-4748-490c-876d-f65f55e81d95` に限ります。
他の無指定の `Corporate Pariah` は読み替えず、未対応のままです。
段階未選択・候補外の段階・文章未記入・`[Corp]` のようなプレースホルダーの直接入力は、
いずれも作成エラーにして、資質を一切付与しません。

これで固定データの325候補すべてが選択可能です。段階や付与内容を確定できない記述は
今後も読み替えず、選択不可のまま理由付きで一覧に残します。

## 実装

`CharacterState.life_modules` は選択順のカタログ ID 一覧、`life_module_choices` は
`選択位置:効果位置` をキーとする追加選択です。選択位置は重複などのエラーがある経歴も含めて維持します。
カタログの `family_id` は親モジュールの ID です。派生版を含めて同じ親の取得は1回に制限します。
JSON などから重複を読み込んだ場合は、後続の重複分を作成エラーにし、効果と費用を加算しません。
保存された一覧は保持するため、画面から重複分を削除して修復できます。
削除時は後続の選択位置を詰めて、残った経歴の選択を維持します。

計算時のみキャラクターのコピーへ付与値を合算し、計算終了時に手動購入値へ戻します。
これにより再計算、JSON 往復、経歴削除で付与が重複したり購入値へ残ったりしません。
固定・選択式の資質付与は既存の無償付与経路へ接続します。
資質グループの段階的付与は最高レベルを採用し、経歴による無料ポイントを資質カルマの計算に反映します。

参照: [固定コミットの Chummer データ](https://github.com/chummer5a/chummer5a/blob/d7e94f6a090f267362757675d05bbe4d7543c217/Chummer/data/lifemodules.xml)。


## 重複取得・技能上限の上流調査（2026-10-12）

Chummer5a の [SelectLifeModule.cs](https://github.com/chummer5a/chummer5a/blob/master/Chummer/Forms/Character%20Creation%20Forms/SelectLifeModule.cs)
は各候補の `RequirementsMetAsync` で選択を絞りますが、同一モジュール・同じ親の派生版を
比較する独自の重複チェックはありません。
共通の [SelectionShared.cs](https://github.com/chummer5a/chummer5a/blob/master/Chummer/Backend/Static/SelectionShared.cs)
でも、`limit` のない `module` / `version` は取得回数無制限として扱います。
固定 `lifemodules.xml` の Bounty Hunter / Corporate には `limit` がありません。
したがって、本アプリの取得回数制限は今回報告されたルールを実装したもので、
Chummer5a の既存の重複制限を移植したものではありません。

技能付与について、[ImprovementMethods.cs](https://github.com/chummer5a/chummer5a/blob/master/Chummer/Backend/Improvements/ImprovementMethods.cs)
の `skilllevel` は `SkillLevel` improvement を作り、
[Skill.cs](https://github.com/chummer5a/chummer5a/blob/master/Chummer/Backend/Skills/Skill.cs)
の `FreeKarma` がこれを無償レベルとして読み取ります。表示上の `Karma` は `RatingMaximum` で制限されます。
この経路に、超過分から同じ関連能力値の技能へ割り振るプールを作る処理は確認できませんでした。
本アプリの超過分の割り振り（[操作](#操作)の 4.）は、Chummer 本体には無い処理です。
