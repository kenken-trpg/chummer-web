# ユドナリウム書き出し

Udonarium（ユドナリウム）のキャラクターコマを 1 体 1 ファイルの `.xml` として
書き出す。ココフォリア書き出し（`frontend/lib/cocofolia.ts`）の兄弟で、プールの
計算はそちらと同じものを使い、器とパレットの書き方だけが違う。

参照したのは手作りのテンプレート `data.xml`（能力値が全部 3 のダミー）。Udonarium の
配布 zip に入っている形で、中身は次の通り。

| 箇所 | 中身 |
| --- | --- |
| ルート `<character>` | 配置と表示の属性（`location.*`・`overViewWidth`・`chatColorCode.*` 等） |
| `common` | 名前・サイズ・高度 |
| `detail` → イニシアティブ/エッジ/移動力 | `numberResource` 3 つ |
| `detail` → コンディション・モニター | 身体 / 精神 / マトリックス CM の `numberResource` と負傷修正の `markdown` |
| `detail` → 立ち絵位置・コマ画像 | 外部スクリプト用のつまみ |
| `<chat-palette dicebot="ShadowRun5">` | 本体。`//敏捷力=3` で変数を定義し `({敏捷力}+{射撃技能A})B6@{射撃精度A}` で参照 |

ダイスは BCDice の `ShadowRun5`（`xB6` / `xB6@L` / エッジは `xR6`）で、ココフォリア
書き出しが出しているものと同じ記法。

## 決めたこと

- **パレットは併用**。主要な攻撃・防御・魔法・マトリックスは変数方式（卓で修正値を
  いじれるのがテンプレートの主眼）。技能一覧や各種判定は確定値を展開する。
- **`.zip`**（`data.xml` 1 枚）。当初は `.xml` 直接にしたが、udonarium.app 1.17.4 の
  入り口は 2 つあって挙動が違う。盤面へのドラッグ＆ドロップは xml 単体を読むが、
  「ZIP読込」のファイル入力は渡されたものを必ず unzip しようとし、xml を
  `End of central directory not found` で落とす（その input の `accept` は
  `application/xml` を挙げているのに）。zip はどちらからも入るので zip にした。
  frontend は実行時依存がゼロなので、`lib/zip.ts` に 1 ファイル分だけの zip
  ライター（無圧縮）を置いた。
- **`detail` はサンプル通り**、リソースだけ。能力値はパレットの変数が持つ。
- **ポートレートは載せない**。`imageIdentifier` は `none_icon` のまま。

ポートレートは入れていないが、器が zip になったので運べるようにはなった。

## 変数の名前

定義 `//名前=値` と参照 `{名前}` は文字列として一致していないと解決されないので、
両方を同じ関数から出す。能力値は `attrName()`（`String_Attribute<KEY>Long`、
例: `敏捷力`）、リミットは `udo.limPhysical` 等の新しいキー（パレット内では
`身体リミット`。シートの `coco.limPhysical` は `身体LIM` で別物）。

サンプルは武器と呪文を A / B の固定枠で持っているが、実際のキャラは何本でも持つので
`A`・`B`・`C`…（26 本を超えたら `AA`…）で採番する。

## 変数方式で出すもの

- 能力値 8 つ（＋魔力・共鳴力があれば）、リミット 3 つ、装甲値
- 射撃武器ごと: `射撃武器X` / `射撃精度X` / `射撃技能X` / `射撃補正X`
- 近接武器ごと: `近接武器X` / `近接精度X` / `近接技能X` / `近接補正X`
- 防御（回避・受け・フル防御）とダメージ抵抗
- 呪文ごと: `呪文X` / `呪文補正X`、呪文行使・儀式呪文行使・召喚・錬金術・霊視、
  ドレイン抵抗
- マトリックス: `アタック` / `スリーズ` / `データ処理` / `ファイアウォール` と
  `ハッキング` / `サイバー戦闘` / `コンピュータ`

キャラが持っていないものは節ごと落とす（呪文を使えないランナーにメイジ用の節は出ない）。
サンプルはテンプレートなので全部入っているが、こちらは実在のキャラを書き出す。

## 確定値で出すもの

イニシアチブ、習得済み技能（特化を含む）と知識技能、未修得技能（`untrained` を
オンにしたとき）、平静・意図看破・記憶・運搬、グレネード散乱、精霊の召喚・束縛・追放。

## 置きかた

- `frontend/lib/vtt-pools.ts` — ココフォリアと共有する部品（`ATTR_LIMIT`・
  `weaponSkill`・技能の能力値表）。`cocofolia.ts` からこちらへ移すだけで、
  振る舞いは変えない。
- `frontend/lib/udonarium.ts` — `buildUdonariumXml()` と、パレットを組む
  `buildUdonariumPalette()`。
- `useCharacterExport` に `downloadUdonarium()`、ツールバーに「ユドナリウム」ボタン。
  ファイル名は `exportFilename(name, "xml", { tag: "udonarium" })`。
- 文言は `udo.*` として `locales/{ja,en}/sheet.ts` に。既定は日本語（ココフォリアと
  同じ理由。Udonarium は日本語の VTT）で、UI の言語に追従する。

バックエンドは触らない。計算は済んだ `derived` から組むので、新しいルートは要らない。

## 精霊とスプライト

束縛済みの精霊と登録済みのスプライトは、1 体 1 コマとして書き出す（ココフォリアの
`buildCocofoliaConjured` と同じ考え方）。ツールバーの「ユドナリウム（精霊コマ）」で
`.zip` が 1 つ落ち、中に `data.xml`・`data_1.xml`… が並ぶ。

計画段階では「`data.xml` はルート要素が 1 つなので無理」としていたが、これは器が
`.xml` だった頃の話。**ユドナリウムは zip の中の xml を全部読む**ので（udonarium.app
1.17.4 で確認）、1 回のドロップで全部が卓に出る。

パレットで変数にするのはフォース（スプライトはレベル）。シート上のリミットは全部
それで、卓で上げ下げするのもそこなので、ロールは書き出し時点の数値ではなく変数を
参照する。フォースから算出済みの能力値はそのまま数値で置く — 変数を動かしても
再計算はされないので、そこは正直に固定値にしてある。

エントリ名（`data_1.xml`）は卓からは見えない。コマの名前は xml の中にあるので、
エントリ名は ASCII で一意なら何でもよく、採番にしている。
