# UI 文言と i18n

アプリには **2 つの独立した文字列レイヤー**があります。混同しないでください。

| レイヤー           | 元                                                                       | アクセス                                                                                                   | 対象                                                                             |
| ------------------ | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| **ゲーム用語**     | Chummer `Chummer/lang/{ja-jp,en-us}.xml` ＋ `backend/data/ja_overrides/` | `catalog.ui_strings[locale]` → `makeT(catalog, locale)` / `makeTr(catalog, locale)`（`lib/ui-strings.ts`） | メタタイプ名、能力値ラベル、資質名、装備名など                                   |
| **アプリ UI 文言** | このリポジトリ内の辞書 `frontend/lib/i18n/locales/`                        | `useUiText().ui(key, vars?)`（`lib/i18n/`）                                                                | タブ名、ボタン、パネル見出し、状態表示、**ルールエンジンの指摘文**（`engine.*`） |

このドキュメントは後者（アプリ UI 文言）の話です。

## 仕組み

```ts
import { useUiText } from "@/lib/i18n";

function Something() {
  const { ui, locale, setLocale } = useUiText();
  return <button>{ui("tab.check")}</button>;
}
```

- ロケールは `ja` / `en`。既定は `ja`。
- `localStorage["chummer-web:locale"]` に保存。`useLocale()` はウィンドウイベントで
  ツリー内の全 `useUiText()` を同期させます（`LocaleSwitch` で切替）。
- **`ja` が基準ロケール**。`locales/ja.ts` の `JA` に全キーを定義し、`MsgKey` はそこから導出されます。
- **文言の実体は分野別のファイル**に分かれています（`locales/ja/app.ts`,
  `engine.ts`, `sheet.ts`, `sidebar.ts`, `rules.ts`, `chargen.ts`, `gear.ts`,
  `magic.ts`。`en/` も同じ 8 枚）。`locales/ja.ts` / `en.ts` はそれらを
  スプレッドでまとめるだけの入口です。1,800 キーを 1 つのオブジェクトに
  置くと動き回りづらいのが理由。
  スプレッドは同じキーがあっても黙って後勝ちになる（TypeScript の TS1117 は
  1 つのオブジェクトリテラルの中でしか出ない）ので、`lib/i18n/locales.test.ts`
  が「どのキーもちょうど 1 ファイルにしかない」ことを見張っています。
- **他のロケールは「完全」であることを型で強制**しています。各辞書は
  `Record<MsgKey, string>` なので、`JA` にキーを足すと**全ロケールが埋まるまで
  `npm run typecheck` が落ちます**。以前 `EN` は `Partial` で、未定義キーは静かに
  日本語へフォールバックしていました。英語話者から見ると「訳し忘れ」と
  「意図的に日本語のまま」が区別できないので、ビルドで止める方を選んでいます。
- `ui("check.summary", { errors, warns, infos })` のように `{name}` プレースホルダを展開できます。
- **バンドルに入るのは `ja` だけ**。他のロケールは `messages.ts` の `LOADERS` にある
  動的 `import()` で、そのロケールを表示する要求が出たときに取りに行きます
  （カタログは 1 枚 38 KiB gzip あり、2 言語を同時に読む人はいないため）。
  `MESSAGES` は**いま手元にあるカタログ**で、`MESSAGES.ja` だけは常に存在します。
  到着前は `translate()` が `ja` を返しますが、`useLocale()` は
  **カタログが届いていないロケールを名乗りません** —— 名乗ってしまうと
  「en のはずの画面が日本語」という中途半端な 1 フレームが出るため、
  `ja` のまま待って、到着時に一度で切り替わります。
  テストは `tests/locales.ts`（両プロジェクトの `setupFiles`）が全ロケールを
  先に読み込みます。読み込み前の挙動そのものは `messages.test.ts` が
  `vi.resetModules()` で、名乗らないことは `index.test.tsx` が見張っています。

## エンジンの指摘文（`engine.*`）

作成チェックの指摘文はバックエンドが作りますが、**文はここにあります**。エンジンは
`{"key": "engine.gear.availOver", "params": {...}}` という `Notice`（`backend/app/notices.py`）
を `derived.errors` / `derived.warnings` に積むだけで、`lib/engine-notices.ts` の
`renderNotice(notice, ui, tr)` が辞書を引いて文にします。

パラメータには 2 つのラッパーがあります。

- `{"tr": "Ares Predator V"}` — カタログ名。`tr` を通すので、**日本語モードでも
  アイテム名が訳されます**（以前は日本語の文に英語名が混ざっていました）。
- `{"ui": "engine.slot.arm"}` — エンジン側の固定語彙（肢の部位、左右、装着先の種別）。
  これも辞書のキーです。

キーは `engine.<領域>.<名前>` で、`<領域>` は `lib/character/checklist.ts` の
`TAB_BY_AREA` がそのままタブへの振り分けに使います（以前の日本語正規表現マッチの
置き換え）。バックエンドにメッセージを足す手順は `backend/app/notices.py` の
docstring と `docs/adding-rules.md` を参照してください。辞書に無いキーは
そのまま `engine.foo.bar` と表示されます（落ちません）。

同じ `Notice` は**指摘文以外の表示用ラベル**にも使っています。支出内訳の各行
（`karma_spend_breakdown` / `nuyen_spend_breakdown` / `career_advancement_lines`
の `notice`）と、ドラッグの効果・持続時間（`active_drugs[].effect` は `Notice[]`、
`duration` は `Notice`）がそれです。`Notice[]` は `renderNotices()` が
`" / "` で繋ぎます。

API のエラーも同じ形です。`HTTPException(detail=...)` が文ではなく `Notice` を
載せ、`lib/api.ts` の `errorText()` が辞書を引きます（キーは `api.*`）。
`chummer_import` は `NoticeError`（`app/notices.py`）でキーを呼び出し元まで
持ち上げます。`errorText()` は React の外で動くので、`useUiText()` ではなく
`readLocale()` + `translate()` でロケールを取ります。

キーと辞書がずれていないかは `backend/tests/test_notice_keys.py` が両方向で
検査します（文言の無いキー／バックエンドが出さないキー）。`f"engine.slot.{...}"`
のように実行時に組み立てる族は `DYNAMIC_FAMILIES` に登録してください。

## キーの追加

1. `frontend/lib/i18n/locales/ja/<分野>.ts` に `"group.name": "日本語"` を足す（型 `MsgKey` が自動で広がる）。
2. `locales/en/<同じ分野>.ts` にも足す（**必須**。抜けると型エラー）。訳語が決まらない場合でも、
   英語として通じる暫定文言を入れて先に進めてください。
3. コンポーネントで `ui("group.name")`。モジュールトップレベルの定数は
   フックを呼べないので、キーだけ持たせてレンダー時に `ui()` を通します。

## ロケールの追加

1. `Locale` に追加し、`LOCALES` に足す。
2. `locales/xx.ts` に `export const XX: Catalog = { … }` を定義し（`ja` / `en` にならって
   `locales/xx/` に分野別に置き、入口でまとめるのが楽です）、`messages.ts` の `LOADERS` に
   `xx: () => import("./locales/xx").then((m) => m.XX)` を足す。**`MESSAGES` に直接
   書かないでください** —— そこは `ja` と、読み込み済みのものだけが入ります。
   静的 import にすると全訪問者がそのカタログを落とすことになります。
   型が全キーを要求するので、埋め終わるまでビルドは通りません。
3. `LocaleSwitch` の選択肢は自称表記（`locale.xx`）を引くので、`locale.xx` キーを
   全ロケールに足すのを忘れずに。

## 未抽出の日本語を増やさない仕組み

**抽出は完了しました。未抽出の日本語リテラルは 0 個です。** 仕組み自体は残して
あります — **新しく増えるぶんを止める**のが本来の役目だからです。

`eslint.config.mjs` の `no-restricted-syntax` が、`app/` `components/` `lib/` の
日本語リテラル（JSX テキスト、`title` / `aria-label` / `placeholder` などの属性、
テンプレートリテラル、代入・返り値の文字列）を **error** にします。記録して見逃す
抑制ファイルはもう無いので、違反は単に落ちます。

`lib/` を対象外にしていた時期があり、`lib/character/bits.tsx` の 2 リテラルが
そのまま残っていました。`lib/` も UI 文言を描画する（テキストシート、
フォーマッタ、小さな JSX 断片）ので今は対象です。除外は辞書そのものである
`lib/i18n/locales/` 以下だけです（`lib/cocofolia.ts` も以前は
除外でしたが、ロケールを受け取るようになったので対象に戻しました）。

```bash
npm run lint            # 新規の日本語リテラルがあれば落ちる
```

かつては残数を数える `eslint-suppressions.json` と、それを操作する
`lint:suppress` / `lint:prune` がありました。残数が 0 になったので、ファイルごと
削除しています。**新しい日本語リテラルを抑制で通す道は用意しません。**

### 文言を足すときの手順

1. 文言を `locales/ja/<分野>.ts` に足す。キー名は `<画面>.<役割>`
   （`toolbar.duplicate`、`sidebar.essence`）。
2. `locales/en/<同じ分野>.ts` にも足す（型が要求するので忘れられません）。
3. コンポーネントで `ui("...")` を通して描く。**モジュールトップレベルの定数配列は
   フックを呼べない**ので、キーだけ持たせてレンダー時に `ui()` を通します。
4. `npm run check`。
5. テストは**アクセシブル名で書かれている**ので、文言を動かすとテストが落ちます。
   それが検出器なので、落ちたら `ui()` 経由の期待値に直してください。

### 対象外

- `lib/i18n/locales/` 以下 — 辞書そのもの。
- `*.test.tsx` — 期待値として日本語を書くのは正しい。
- `app/layout.tsx` / `app/share/layout.tsx` の `metadata`（`<title>` と
  `description`）は、リテラルではなく `translate("ja", ...)` で辞書から引いて
  いますが、**ロケールは `ja` に固定**です。Next の静的 `Metadata` はサーバ側で
  ビルド時に評価されるのに対し、ロケールはブラウザの `localStorage` にしか
  ありません。ここを本当に多言語化するには URL かクッキーにロケールを持たせる
  必要があり、それは別の設計判断です。

## ツールチップヘルプ（`HelpTip`）

画面の値の横にある「?」は、すべて `frontend/components/help/HelpTip.tsx` で描きます。
`title=` 属性や自作のツールチップは使いません。`HelpTip` は次の 2 つをまとめて引き受けます。

- 開き方：マウスを載せる・キーボードでフォーカスする・タップする、のどれでも開く（スマホにはホバーが無い）。
- 読み上げ：`aria-describedby` でボタンと説明を結ぶので、スクリーンリーダーも説明を読む。

説明の箱は、いちばん近いスクロールする祖先（たいていサイドバー）からはみ出さないよう、開くときに位置を測り直します。
なお、grep で探すときの名前は `HelpTip` です（`Tooltip` では当たりません）。

`title=` を残してよいのは、説明ではなく、画面に出ている値の補足だけです。今は次の 2 つです。

- `SpecPicker` の選択肢：欄が狭くて切れた専門化の名前の全文。
- シートの命中・ダメージの欄：その値を出した式。

ほかに説明の置き場が要るときの形は次のとおりです。

- **タブ**：開いているタブの説明は、パネルの先頭の 1 行（`tab.<名前>.hint`）。装備の種類も同じです。
- **行ごとのボタン**：見えている文字を先頭にした `aria-label` で、どの行のボタンかを名乗ります（例：「戻す：{名前}」）。
- **書き出しのメニュー**：項目ごとに「?」を付けます。メニューは「?」を押しても閉じません（`Menu` の `onPick`）。

### 書き方

```tsx
<HelpTip
  label={ui("help.open", { label: ui("help.cf.pointsLabel") })}
  lines={[{ label: ui("help.cf.pointsFree") }, { label: ui("help.cf.pointsPaid") }]}
>
  {ui("help.cf.pointsLabel")}
</HelpTip>{" "}
{ui("cf.free", { used, free })}
```

- **`children`**：「?」の左に出る見出しです。行そのものの値（ここでは `cf.free`）は外に置きます。
- **`label`**：ボタンのアクセシブル名で、必ず `help.open`（「{label} の説明」）を通します。
- **`lines`**：説明の行です。行ごとに `value`（右に寄せる数値）と `strong`（強調）を付けられます。
  内訳を見せるときは、`help.base`／`help.bonus`／`help.total` を `value` と組み合わせます。

### 文言

- 文言は `locales/ja/help.ts` と `locales/en/help.ts` に置きます。
- キー名は `help.<画面>.<役割>` です。見出しは `help.<画面>.statsLabel`（行の値）か、`help.<画面>.<何>Label` にします。
- **1 行に 1 つの事実**を書きます。
- **書く前にバックエンドの計算を読みます。** 説明は、エンジンが実際にしていることと食い違ってはいけません。
  - 設定で変わる値は数字で言い切りません（例：コンタクトの倍率は `free_mult` を差し込む）。
  - 資質で変わる値は「資質で変わる」と書きます。
- 計算式は `身体リミット = (STR×2 + BOD + REA) ÷ 3（切り上げ）` のように書きます。頁は `SR5 p.47` の形にします。
  演算子の前後の空白と、`SR5 p.` の空白は、`bindRuns()` が改行しない空白に置き換えます。辞書に `\u00a0` は書きません。
- 用語は [訳語の一覧](translation-glossary.md) から引きます。
  ja の辞書に触れたら、backend の `tests/test_ja_terms.py` も回します（禁止語は [translation-banned-terms.md](translation-banned-terms.md)）。
- ルールブックの文は写しません（`NOTICE.txt`）。説明は自前の文で書き、典拠は語と頁だけにします。

### 守っているテスト

`frontend/components/help/help-coverage.test.ts` が、ソースを読んで次の 3 つを確かめます。

1. **ヘルプの無いタブを作らない**：すべてのタブとサイドバーの節が、自身か子のコンポーネントで `HelpTip` を描く。
   例外にするときは `WITHOUT_HELP` に理由を書く（今は空）。
2. **ボタン名は `help.open` で付ける**。
3. **使われていない `help.*` キーを残さない**：行を動かしてヘルプを外したら、辞書からも消す。

コンポーネントのテストは、名前で引きます。

```tsx
expect(screen.getByRole("button", { name: "複合体の無料枠 の説明" })).toBeDefined();
expect(screen.getByText(/共振の欄で選んだタレント/)).toBeDefined();
```

e2e では「?」を**クリックせずに `focus()` で開きます**。スマホ幅では、上に貼り付いたタブバーが最初の行に重なり、クリックがバーに当たって
時間切れになることがあるためです（#680）。

## `tr` と `ui` の線引き

シートに着手するとき、ラベルがゲーム用語に近いので線引きが要ると考えていましたが、
実際に数えると争点がありませんでした。シート内の `tr(...)` 呼び出しは 61 箇所あり、
**カタログ由来の名前はすべて既に `tr` を通っていて**、直書きの文字列でカタログの
名前だったものは 1 つもありませんでした。

- **カタログから出てきた値**（`item.name`、`item.category`、`d.lifestyle.name`）→ `tr`
- **アプリが書いた文字列**（見出し、表のヘッダ、ステータス名、単位、説明文）→ `ui`

判断が要るのは「ゲーム用語だがカタログの行ではないラベル」だけです
（`身体リミット`、`ダメージ抵抗`、`非武装DV`、`冷静`、`意図を測る`、`記憶`）。
引くべき行が存在しないので `ui` に置き、英語側には実際の SR5 の用語
（Physical Limit、Composure、Judge Intentions、Memory）を入れています。

この層の日本語は語感で決めず、`translation-glossary.md`（自動生成の正典）を引きます。
上の `身体リミット` がその例で、リポジトリ全体が `物理リミット` と書いていたのを正典に
合わせて直しました。正典との照合は全自動にはできません — 日本語の文からは、どの英語用語の
訳なのかが復元できないためです。そこで一度直した誤りだけを
[`translation-banned-terms.md`](translation-banned-terms.md) に記録し、
`scripts/check_ja_terms.py`（`make check-i18n`、バックエンドのテストからも走ります）が
`frontend/lib/i18n/locales/ja/` を走査して再発を落とします。新しいずれを直したら 1 行足します。

## ゲーム用語レイヤーの 2 つの表

この層は**別々の 2 つの表**でできています。混同すると片方だけ英語になります。

**`translations`（`tr`）— カタログの名前**。Chummer のデータファイルは英語なので、
この表は「英語名 → 日本語名」です。したがって **`en` では `tr` は恒等関数**です。
上流に `en-us_data.xml` は存在しません。訳すものが無いからです。

**`ui_strings`（`t`）— UI 文字列キー**。`ja-jp.xml` と `en-us.xml` の
`<string key><text>` を読みます（`en-us.xml` は元から
`fetch_chummer_data.py` が取得していて、読まれていなかっただけです）。
アプリがこの表を引くのは `attrShort` / `attrName` / `attrLabel` **だけ**で、
組み立てるキーは `String_Attribute<KEY>Short|Long` に限られます。

lang ファイルは 1 ロケールあたり約 2,600 キーあります。2 ロケール分をそのまま
載せると、既に 2.9 MB あるカタログに読まれない文字列を約 330 KB 積むことになるので、
`public_catalog` は **`String_Attribute*` ＋ `ja_overrides/ui.json` の全キー**に
絞って配信します（57 キー / ロケール）。ui.json を含めるのは、あれが手作業で
選んで訳した集合だからです — 今日読まれていないというだけで捨てると、その作業が
黙って消えます。新しいキーを読む前に `UI_STRING_PREFIXES` を広げるか
ui.json に足してください。取りこぼしても致命的ではありません
（`makeT` は呼び出し側の既定値 → キー自身の順にフォールバックします）が、
`String_Foo` がそのまま画面に出ます。

**カタログのサイズは 2,897,065 → 2,724,478 バイト**に減りました。英語を足して
なお 173 KB 小さくなっています。

なお **`ja_overrides/ui.json` は `ja` にしか適用しません**。あれは同梱の日本語を
直すためのもので、英語の原文には言うことがありません。

### 導師精霊の利点・欠点は文を出さない

導師精霊（とパラゴン）の利点・欠点は、Chummer のデータの英文も、自前の日本語の要約も
画面に出しません。どちらもルールブックの本文に当たるからです（`NOTICE.txt`：ルール本文は
再録しない）。代わりに出典の頁（Chummer のデータにある英語版の頁）と、「利点は計算に反映済み」
「欠点は特定の状況で適用、ルールブック参照」の固定の文を出します。

- 以前あった文の表 `ja_overrides/texts.json`（`makeTextTr`）は、このために外しました。
- `.chum5` の書き出しは `<advantage>`/`<disadvantage>` に Chummer のデータの文を書いたままです。
  Chummer が自分のセーブに書く欄で、画面には出ません。
- 日本語版の頁はまだ持っていません（TODO）。

### VTT 書き出しは既定が日本語

`lib/cocofolia.ts` と `lib/udonarium/` の各ビルダーは `locale: Locale = "ja"` を
取ります。ツールバーから呼ぶときは UI のロケールを渡すので言語切替に追従し、引数を
省いた呼び出し（テストなど）は日本語のままです。どちらも日本語の VTT で、コマは
日本語卓の部屋に貼られるものなので、既定を日本語に置いています。

ラベルは辞書の `coco.*` と `udo.*` にあります。ダイスコマンド（`9B6@3`）は BCDice の
記法なので翻訳の対象外です。

ユドナリウムのパレットは変数方式（`//敏捷力=5` と `{敏捷力}`）なので、`udo.var*` は
**ラベルではなく識別子**です。定義と参照は同じキーから出すので一致しますが、値に
`{`・`}`・`=`・`/`・空白を入れるとパレットが解決できません（`varName()` が落とします）。
