# UI 文言と i18n

アプリには **2 つの独立した文字列レイヤー**があります。混同しないでください。

| レイヤー | 元 | アクセス | 対象 |
|---|---|---|---|
| **ゲーム用語** | Chummer `Chummer/lang/ja-jp.xml` ＋ `backend/data/ja_overrides/` | `catalog.ui_strings` → `makeT()` / `t(key, fallback)`（`lib/ui-strings.ts`） | メタタイプ名、能力値ラベル、資質名、装備名など。日本語のみ（英語版は上流の別 lang ファイルが必要） |
| **アプリ UI 文言** | このリポジトリ内の辞書 `frontend/lib/i18n/messages.ts` | `useUiText().ui(key, vars?)`（`lib/i18n/`） | タブ名、ボタン、パネル見出し、状態表示など、コードに直書きしていた日本語 |

このドキュメントは後者（アプリ UI 文言）の話です。

## 仕組み

```ts
import { useUiText } from "@/lib/i18n";

function Something() {
  const { ui, locale, setLocale } = useUiText();
  return <button>{ui("tab.check")}</button>;
}
```

- ロケールは `ja` / `en`。既定は `ja`。
- `localStorage["chummer-web:locale"]` に保存。`useLocale()` はウィンドウイベントで
  ツリー内の全 `useUiText()` を同期させます（`LocaleSwitch` で切替）。
- **`ja` が基準ロケール**。`messages.ts` の `JA` に全キーを定義し、`MsgKey` はそこから導出されます。
- **他のロケールは「完全」であることを型で強制**しています。各辞書は
  `Record<MsgKey, string>` なので、`JA` にキーを足すと**全ロケールが埋まるまで
  `npm run typecheck` が落ちます**。以前 `EN` は `Partial` で、未定義キーは静かに
  日本語へフォールバックしていました。英語話者から見ると「訳し忘れ」と
  「意図的に日本語のまま」が区別できないので、ビルドで止める方を選んでいます。
- `ui("check.summary", { errors, warns, infos })` のように `{name}` プレースホルダを展開できます。

## キーの追加

1. `frontend/lib/i18n/messages.ts` の `JA` に `"group.name": "日本語"` を足す（型 `MsgKey` が自動で広がる）。
2. `EN` にも足す（**必須**。抜けると型エラー）。訳語が決まらない場合でも、
   英語として通じる暫定文言を入れて先に進めてください。
3. コンポーネントで `ui("group.name")`。モジュールトップレベルの定数は
   フックを呼べないので、キーだけ持たせてレンダー時に `ui()` を通します。

## ロケールの追加

1. `Locale` に追加し、`LOCALES` に足す。
2. `messages.ts` に `const XX: Catalog = { … }` を定義して `MESSAGES` に登録。
   型が全キーを要求するので、埋め終わるまでビルドは通りません。
3. `LocaleSwitch` の選択肢は自称表記（`locale.xx`）を引くので、`locale.xx` キーを
   全ロケールに足すのを忘れずに。

## 未抽出の日本語を増やさない仕組み

コンポーネント側にはまだ **936 個**の日本語リテラルが残っています（`app/` と
`components/` の 72 ファイル）。全部を一度に抽出するのは 1 コミットに見合わないので、
**新しく増えるぶんだけを止める**構えにしています。

`eslint.config.mjs` の `no-restricted-syntax` が、`app/` と `components/` の中の
日本語リテラル（JSX テキスト、`title` / `aria-label` / `placeholder` などの属性、
テンプレートリテラル、代入・返り値の文字列）を **error** にします。既存ぶんは
`frontend/eslint-suppressions.json` に記録済みなので落ちません。

```bash
npm run lint            # 新規の日本語リテラルがあれば落ちる
npm run lint:suppress   # 既存として記録する（原則、使わない）
npm run lint:prune      # 抽出して消えたぶんを抑制ファイルから削る
```

**この抑制ファイルが残数カウンタです。** 抽出したのに `lint:prune` を忘れると
「もう起きない抑制が残っている」として ESLint が exit 2 で落ちるので、数字が
実態から乖離しません。

### 抽出の手順（1 バッチぶん）

1. 対象ファイルを 1 つ選ぶ（残数の多い順は `eslint-suppressions.json` を見る）。
2. 文言を `messages.ts` の `JA` に足す。キー名は `<画面>.<役割>`
   （`toolbar.duplicate`、`sidebar.essence`）。
3. `EN` にも足す（型が要求するので忘れられません）。
4. コンポーネントを `ui("...")` に書き換える。**モジュールトップレベルの定数配列は
   フックを呼べない**ので、キーだけ持たせてレンダー時に `ui()` を通します。
5. `npm run lint:prune` → `npm run check`。
6. テストは**アクセシブル名で書かれている**ので、文言を動かすとテストが落ちます。
   それが検出器なので、落ちたら `ui()` 経由の期待値に直してください。

### 対象外

- `lib/**` — 日本語の**データ表**（`SPIRIT_ROLE_JA`、cocofolia のパレット、
  `KNOW_CAT_JA`）が混ざっており、UI 文言とは別の問題です。
- `lib/i18n/messages.ts` — 辞書そのもの。
- `*.test.tsx` — 期待値として日本語を書くのは正しい。
- `lib/character/checklist.ts` の動的な指摘文 — バックエンドの日本語メッセージに
  合わせているため、英語化はサーバ側と揃える必要があります（下記参照）。

## 現状（scaffold）

`ja`/`en` 両対応に移行済み:

- アプリシェル：`app/page.tsx` の読み込み表示・タグライン
- タブバー：`components/character/TabBar.tsx` の全タブ名
- 作成チェックパネル：`components/character/ChecklistPanel.tsx` の見出し・要約・ボタン
- 言語切替：`components/LocaleSwitch.tsx`
- **ツールバー：`components/character/Toolbar.tsx` 全体**（ボタン、`title`、
  `aria-label`、`window.confirm` の文言まで。35 キー）

**未移行**（`ja` 直書きのまま。同じ要領で `messages.ts` に寄せれば動く）:

- 各タブ本体（`components/character/tabs/*`）、サイドバー（`components/character/sidebar/*`）
- エディタのプロンプト／確認／エラー文言（`lib/character/useCharacterEditor.ts`）
- `lib/character/constants.ts` のラベル表（`CATS`, `KNOW_CAT_JA`, `SPIRIT_ROLE_JA` ほか）
- 作成チェックの**動的な指摘文**（`lib/character/checklist.ts`）はエンジン（バックエンド）の
  日本語メッセージに合わせているため日本語固定。英語化するならバックエンド側の文言も揃える必要があります。
