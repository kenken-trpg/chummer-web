# UI 文言と i18n

アプリには **2 つの独立した文字列レイヤー**があります。混同しないでください。

| レイヤー | 元 | アクセス | 対象 |
|---|---|---|---|
| **ゲーム用語** | Chummer `Chummer/lang/{ja-jp,en-us}.xml` ＋ `backend/data/ja_overrides/` | `catalog.ui_strings[locale]` → `makeT(catalog, locale)` / `makeTr(catalog, locale)`（`lib/ui-strings.ts`） | メタタイプ名、能力値ラベル、資質名、装備名など |
| **アプリ UI 文言** | このリポジトリ内の辞書 `frontend/lib/i18n/messages.ts` | `useUiText().ui(key, vars?)`（`lib/i18n/`） | タブ名、ボタン、パネル見出し、状態表示など、コードに直書きしていた日本語 |

このドキュメントは後者（アプリ UI 文言）の話です。

## 仕組み

```ts
import { useUiText } from "@/lib/i18n";

function Something() {
  const { ui, locale, setLocale } = useUiText();
  return <button>{ui("tab.check")}</button>;
}
```

- ロケールは `ja` / `en`。既定は `ja`。
- `localStorage["chummer-web:locale"]` に保存。`useLocale()` はウィンドウイベントで
  ツリー内の全 `useUiText()` を同期させます（`LocaleSwitch` で切替）。
- **`ja` が基準ロケール**。`messages.ts` の `JA` に全キーを定義し、`MsgKey` はそこから導出されます。
- **他のロケールは「完全」であることを型で強制**しています。各辞書は
  `Record<MsgKey, string>` なので、`JA` にキーを足すと**全ロケールが埋まるまで
  `npm run typecheck` が落ちます**。以前 `EN` は `Partial` で、未定義キーは静かに
  日本語へフォールバックしていました。英語話者から見ると「訳し忘れ」と
  「意図的に日本語のまま」が区別できないので、ビルドで止める方を選んでいます。
- `ui("check.summary", { errors, warns, infos })` のように `{name}` プレースホルダを展開できます。

## キーの追加

1. `frontend/lib/i18n/messages.ts` の `JA` に `"group.name": "日本語"` を足す（型 `MsgKey` が自動で広がる）。
2. `EN` にも足す（**必須**。抜けると型エラー）。訳語が決まらない場合でも、
   英語として通じる暫定文言を入れて先に進めてください。
3. コンポーネントで `ui("group.name")`。モジュールトップレベルの定数は
   フックを呼べないので、キーだけ持たせてレンダー時に `ui()` を通します。

## ロケールの追加

1. `Locale` に追加し、`LOCALES` に足す。
2. `messages.ts` に `const XX: Catalog = { … }` を定義して `MESSAGES` に登録。
   型が全キーを要求するので、埋め終わるまでビルドは通りません。
3. `LocaleSwitch` の選択肢は自称表記（`locale.xx`）を引くので、`locale.xx` キーを
   全ロケールに足すのを忘れずに。

## 未抽出の日本語を増やさない仕組み

コンポーネント側の未抽出の日本語リテラルは **2 個**まで減りました（`app/layout.tsx` と
`app/share/layout.tsx` の `metadata`。理由は「対象外」に書いてあります）。
仕組み自体は残してあります — **新しく増えるぶんを止める**のが本来の役目だからです。

`eslint.config.mjs` の `no-restricted-syntax` が、`app/` と `components/` の中の
日本語リテラル（JSX テキスト、`title` / `aria-label` / `placeholder` などの属性、
テンプレートリテラル、代入・返り値の文字列）を **error** にします。既存ぶんは
`frontend/eslint-suppressions.json` に記録済みなので落ちません。

```bash
npm run lint            # 新規の日本語リテラルがあれば落ちる
npm run lint:suppress   # 既存として記録する（原則、使わない）
npm run lint:prune      # 抽出して消えたぶんを抑制ファイルから削る
```

**この抑制ファイルが残数カウンタです。** 抽出したのに `lint:prune` を忘れると
「もう起きない抑制が残っている」として ESLint が exit 2 で落ちるので、数字が
実態から乖離しません。

### 抽出の手順（1 バッチぶん）

1. 対象ファイルを 1 つ選ぶ（残数の多い順は `eslint-suppressions.json` を見る）。
2. 文言を `messages.ts` の `JA` に足す。キー名は `<画面>.<役割>`
   （`toolbar.duplicate`、`sidebar.essence`）。
3. `EN` にも足す（型が要求するので忘れられません）。
4. コンポーネントを `ui("...")` に書き換える。**モジュールトップレベルの定数配列は
   フックを呼べない**ので、キーだけ持たせてレンダー時に `ui()` を通します。
5. `npm run lint:prune` → `npm run check`。
6. テストは**アクセシブル名で書かれている**ので、文言を動かすとテストが落ちます。
   それが検出器なので、落ちたら `ui()` 経由の期待値に直してください。

### 対象外

- `lib/**` — 日本語の**データ表**（`SPIRIT_ROLE_JA`、cocofolia のパレット、
  `KNOW_CAT_JA`）が混ざっており、UI 文言とは別の問題です。
- `lib/i18n/messages.ts` — 辞書そのもの。
- `*.test.tsx` — 期待値として日本語を書くのは正しい。
- `lib/character/checklist.ts` の動的な指摘文 — バックエンドの日本語メッセージに
  合わせているため、英語化はサーバ側と揃える必要があります（下記参照）。
- `app/layout.tsx` / `app/share/layout.tsx` の `metadata`（`<title>` と
  `description`）。Next の静的 `Metadata` はサーバ側でビルド時に評価されるのに対し、
  ロケールはブラウザの `localStorage` にしかありません。ここを多言語化するには
  URL かクッキーにロケールを持たせる必要があり、それは別の設計判断です。

## `tr` と `ui` の線引き

シートに着手するとき、ラベルがゲーム用語に近いので線引きが要ると考えていましたが、
実際に数えると争点がありませんでした。シート内の `tr(...)` 呼び出しは 61 箇所あり、
**カタログ由来の名前はすべて既に `tr` を通っていて**、直書きの文字列でカタログの
名前だったものは 1 つもありませんでした。

- **カタログから出てきた値**（`item.name`、`item.category`、`d.lifestyle.name`）→ `tr`
- **アプリが書いた文字列**（見出し、表のヘッダ、ステータス名、単位、説明文）→ `ui`

判断が要るのは「ゲーム用語だがカタログの行ではないラベル」だけです
（`物理リミット`、`ダメージ抵抗`、`非武装DV`、`沈着`、`意図看破`、`記憶`）。
引くべき行が存在しないので `ui` に置き、英語側には実際の SR5 の用語
（Physical Limit、Composure、Judge Intentions、Memory）を入れています。

## ゲーム用語レイヤーの 2 つの表

この層は**別々の 2 つの表**でできています。混同すると片方だけ英語になります。

**`translations`（`tr`）— カタログの名前**。Chummer のデータファイルは英語なので、
この表は「英語名 → 日本語名」です。したがって **`en` では `tr` は恒等関数**です。
上流に `en-us_data.xml` は存在しません。訳すものが無いからです。

**`ui_strings`（`t`）— UI 文字列キー**。`ja-jp.xml` と `en-us.xml` の
`<string key><text>` を読みます（`en-us.xml` は元から
`fetch_chummer_data.py` が取得していて、読まれていなかっただけです）。
アプリがこの表を引くのは `attrShort` / `attrName` / `attrLabel` **だけ**で、
組み立てるキーは `String_Attribute<KEY>Short|Long` に限られます。

lang ファイルは 1 ロケールあたり約 2,600 キーあります。2 ロケール分をそのまま
載せると、既に 2.9 MB あるカタログに読まれない文字列を約 330 KB 積むことになるので、
`public_catalog` は **`String_Attribute*` ＋ `ja_overrides/ui.json` の全キー**に
絞って配信します（57 キー / ロケール）。ui.json を含めるのは、あれが手作業で
選んで訳した集合だからです — 今日読まれていないというだけで捨てると、その作業が
黙って消えます。新しいキーを読む前に `UI_STRING_PREFIXES` を広げるか
ui.json に足してください。取りこぼしても致命的ではありません
（`makeT` は呼び出し側の既定値 → キー自身の順にフォールバックします）が、
`String_Foo` がそのまま画面に出ます。

**カタログのサイズは 2,897,065 → 2,724,478 バイト**に減りました。英語を足して
なお 173 KB 小さくなっています。

なお **`ja_overrides/ui.json` は `ja` にしか適用しません**。あれは同梱の日本語を
直すためのもので、英語の原文には言うことがありません。

### ココフォリア書き出しは日本語固定

`lib/cocofolia.ts` は `makeT(catalog, "ja")` と明示的に書いてあります。
ココフォリアは日本語の VTT で、コマは日本語卓の部屋に貼られるものなので、
UI のロケールに関わらず日本語で出します。

## 現状（scaffold）

`ja`/`en` 両対応に移行済み:

- アプリシェル：`app/page.tsx` の読み込み表示・タグライン
- タブバー：`components/character/TabBar.tsx` の全タブ名
- 作成チェックパネル：`components/character/ChecklistPanel.tsx` の見出し・要約・ボタン
- 言語切替：`components/LocaleSwitch.tsx`
- **ツールバー：`components/character/Toolbar.tsx` 全体**（ボタン、`title`、
  `aria-label`、`window.confirm` の文言まで。35 キー）
- **共有ピッカー：`CatalogPicker` / `PickerFootnote`**（`note` が `MsgKey` に
  なったので、呼び出し側も文字列を持てなくなりました）
- **資質タブ：`QualitiesTab` ＋ `QualityExtraEditor`**（資質ごとの対象選択 17 種）
- **アデプトタブ：`AdeptTab`**（パワー、Enhancement、気焦点）
- **技能タブ：`SkillsTab`**（グループ／アクティブ／Exotic／知識）
- **魔法系タブ：`SpellsTab` / `SpiritsTab` / `FociTab`**（共通ぶんは `magic.*`）
- **レゾナンス系タブ：`SpritesTab` / `ComplexFormsTab`**（共通ぶんは `res.*`）
- **成長タブ：`InitiationTab` / `SubmersionTab`**（双子なので共通ぶんは `grade.*`）
- **優先度タブ：`PriorityTab`**（Priority / Sum-to-Ten / Karma の3方式）
- **コンタクト：`ContactsTab`**、**武道：`MartialTab`**
- **ギア枠：`GearTab`**（12個の種別タブ）と**ギアパネル全 10 種**
  （`ArmorGear` / `WeaponGear` / `CommlinkGear` / `CyberdeckGear` / `RccGear` /
  `OpticsGear` / `SensorGear` / `VehicleDroneGear` / `MiscDrugsGear` / `LifestyleGear`）
- **ウェア：`CyberTab` / `BioTab` / `WareRow`**（共通ぶんは `ware.*`）
- **`AddonSelect`**（`装着` の既定ラベルが辞書から来るようになりました）
- **共有部品：`SheetDescEditor` / `ExtraSelect` / `MentorPicker` /
  `SkillPickSelects` / `SpecPicker`**、**`MetaTab` / `AttrsTab`**、
  シートのフッター、**エラー境界 `app/error.tsx` / `app/global-error.tsx`**
- **シート表示：`components/character/sheet/**` 全体**（ヘッダ、全 17 セクション、
  車両ブロック、印刷レイアウトの 2 ブロック）。`Section` は `title` に `MsgKey` を
  取るので、セクションが自分の見出しを直書きできません
- **サイドバー：`components/character/sidebar/*` 9 ブロック全体**（104 キー）。
  `ui` は各ブロックが自前でフックを呼ぶのではなく `SidebarBlockProps` で
  受け取ります（`tr` / `t` と同じ流し方。サイドバー全体が 1 回の
  `useUiText()` で再レンダーされます）

**未移行**（`ja` 直書きのまま。同じ要領で `messages.ts` に寄せれば動く）:

- エディタのプロンプト／確認／エラー文言（`lib/character/useCharacterEditor.ts`）
- `lib/character/constants.ts` のラベル表（`CATS`, `KNOW_CAT_JA`, `SPIRIT_ROLE_JA` ほか）
- 作成チェックの**動的な指摘文**（`lib/character/checklist.ts`）はエンジン（バックエンド）の
  日本語メッセージに合わせているため日本語固定。英語化するならバックエンド側の文言も揃える必要があります。
