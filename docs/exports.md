# 書き出しガイド（使う側の文書）

このアプリで作ったキャラクターを、他のツールへ持っていくための文書です。
ツールバーのボタン 1 つがこの文書の 1 節に対応します。

実装の設計意図は `docs/plans/` の各計画書にあります。ここに書くのは
**何が出るか・どう取り込むか・何が落ちるか**だけです。

| ボタン | 出るもの | 相手 | 欠落の事前通知 |
| --- | --- | --- | --- |
| `JSON保存` | `.json` | このアプリ自身 | — （無劣化） |
| `.chum5書出` | `.chum5`（XML） | Chummer5a | あり |
| `.xlsx書出` | `.xlsx` | ［SR5］キャラシテンプレート | あり |
| `FVTT書出` | `.json` | Foundry VTT（shadowrun5e） | あり |
| `ココフォリア` | クリップボード（JSON） | ココフォリア | — |
| `チャットパレット` | クリップボード（テキスト） | ココフォリア等 | — |
| `精霊コマ` | クリップボード（JSON 配列） | ココフォリア | — |
| `ユドナリウム` | `.zip` | ユドナリウム | — |
| `ユドナリウム（お供のコマ）` | `.zip`（種類ごと） | ユドナリウム | — |

ファイル名は `<キャラ名>-<種類>_<日時>.<拡張子>` の形です（`frontend/lib/character/export-filename.ts`）。

## 書き出す前に出る確認

`.chum5` / `.xlsx` / `FVTT` の 3 つは、**ファイルを書く前に「この書き出しで何が
落ちるか」を一覧で出します**（`ExportReview`）。「このまま書き出す」か「やめる」の
2 択で、落ちること自体は珍しくありません（Chummer に行のない独自アイテム、
キャラシートにセルのないコモンリンク内のプログラムなど）。

仕組みは形式ごとに違います。

- **`.chum5` と `.xlsx`** は、実際に書き出してこのアプリ自身で読み直し、
  差分を取ります。推測ではないので、シートの構成が変わっても報告は自動で正しいままです。
- **`FVTT`** は Foundry の取り込みを再現しません。既知の欠落（メタタイプ固有の
  生得パワー）を挙げるだけです。

**取り込み未確定の装備行も件数に入ります。** 読み込み時に候補が絞れなかった装備は
このブラウザだけに保留されていて、サーバーにも共有リンクにも行きません。確定前に
書き出したファイルにはその行が入りません。

## JSON保存（このアプリ用）

**何が出るか** — キャラクターの入力そのまま。このアプリの `読込` で元に戻ります。
劣化はありません。バックアップと、ブラウザをまたぐ持ち運びはこれが確実です。

**注意** — キャラクターはブラウザの IndexedDB にあり、サーバーには保存されません。
ブラウザのデータを消すとキャラクターも消えます。

## .chum5書出（Chummer5a）

**何が出るか** — Chummer5a が開ける非圧縮 XML の `.chum5`。
`.chum5lz`（圧縮形式）では書き出しません（読み込みは両方できます）。

**取り込み手順** — Chummer5a で *File > Open* から開きます。

**既知の制限**

- 行の id は書き出しのたびに振り直されます。差分を取る用途には向きません。
- キャリアモードのキャラクターは、Chummer が「現在値と残高」で持つのに対し
  このアプリは「作成時の基準値」も持つため、成長分の記録の持ち方が変わります。
  往復しても残カルマは一致しますが、内訳の表現が変わるので確認に出ます。
- このアプリ側の往復（書き出し → このアプリで読み直し）で何が変わるかは確認で
  分かりますが、**Chummer.exe 自身がどう読むかは別**です。そちらは
  `scripts/chum5_reconcile.py --fidelity` が見ています（開発者向け）。
- **一部の効果は、Chummer では効かない状態で開かれます。**
  Chummer は開くときに効果を計算し直さず、ファイルに保存された改善効果だけを
  使いますが、このアプリが書くのはその一部です。資質については、素質
  （Magician・Adept など）が開くタブと技能、資質に書いた文字（Wanted の内容
  など）、導師精霊、技能の値段（College Education など）、移動力やモニターなど
  数で表せる効果（呪文のドレイン・複合体のフェイディングの増減を含む）、資質が付ける資質、資質が付けるクリッター・パワーの効果
  （Hardened Armor のアーマーなど）、Technomancer の Living Persona、限界値の
  修正（Impassive など）、能力値の上限の変更（Exceptional Attribute など）、
  使えなくなる技能や呪文・精霊の種別の制限（Null Wizard・Elementalist・Chain Breaker
  など）、呪文の種別ごとのドレインとダメージ（Death Dealer など）を書きます。
  伝統の効果（Pariah の使えない技能、Toxic の精霊、Missionist の呪文の種別）も書きます。
  フォーカスを結ぶカルマの割引（The Artisan's Way など）と、格闘技スタイルなどが選ばせる
  専門化も書きます。設定「格闘技スタイルの専門化を無料にする」がオンなら、スタイルが選ばせる
  専門化を取ったとき、それを無料の専門化として書き、スタイルに結び付けます（Chummer でスタイルを
  消すと専門化も消えます）。Chummer 自身はこの設定で専門化を自動で足しますが、費用を取る形で
  作るので、このアプリの数字に合わせて無料にしています。取っていない技能には足しません。サイバーウェア・バイオウェア・アデプトパワーの効果もレーティングに
  合わせて書き（能力値に結びついた技能を上げる Neural Amplifiers・Qualia なども含む）、導師精霊の効果（選んだ選択肢の分を含む）も書きます。無料レベルを
  受けるパワーを買っていなければ、レーティング 0 のパワーとして足します。アーマーと
  その改造の効果（耐火・耐電・化学防護、限界値の修正など）も書き、着ていない
  アーマーの分は Chummer と同じく無効にしておきます。装備の効果（Fake License の
  免許、Gas Mask の免疫、Medkit の限界値の修正など）と、結んだフォーカスの効果
  （Weapon Focus の武器、Power Focus、Qi Focus のパワーなど）も書きます。乗り物の
  装備は、乗り物に最初から付いてくるもの（Caduceus の Medkit、ドローンのオートソフトなど）の
  効果だけを書きます。Chummer も、後から積んだ装備には効果を作りません。フォーカスの伝統は、
  まだ書きません。
- **2019 年より前の Chummer の Mentor's Mask は、資質として読みます。** 当時は導師精霊に
  印を付けて取り、今の Chummer では 0 カルマの資質 Mentor's Mask になっています
  （効果はパワーポイント +1・ドレイン −1 で同じ）。印だけのセーブを読むと資質を足し、
  そう伝えます。書き出しでは資質として書きます。
  ライフスタイルの資質で選んだテキスト（Public Transportation の利用先など）も
  Chummer が読む改善効果として書きます。
  Resonant Stream: Technoshaman がスプライトを縛れることも書きます（縛る操作は
  このアプリには無く、Chummer で行います）。
  呪文で選んだもの（Increase [Attribute] の能力値など）も、呪文の `<extra>` と
  Chummer が呪文から作る改善効果として書きます。
  エッセンスの減少による魔力・共鳴力・深度の上限の低下は書きません。これは
  Chummer が開くたびに自分で計算し直します。
  Chummer の *Special > Re-apply Improvements*（特殊 → Improvements の再適用）で
  資質の効果は付きますが、クリッター・パワーの効果が 2 重になります
  （[確認の記録](fixtures/critter-powers/README.md)）。

## .xlsx書出（［SR5］キャラシテンプレート）

音の兔（ねのうさ）様の「［SR5］キャラシテンプレート」（シャドウラン5th 日本版
非公式wiki で紹介）と**同じシート構成・同じ入力セル**の `.xlsx` を書き出します。

**テンプレート自体は同梱していません。** 配布物の `.xlsx` には死んだ Google
スプレッドシートの数式が残っているため、こちらが作るのは「同じ形の入力欄を持つ
ブック」です。このアプリの `読込` で読み直せます。

**取り込み手順** — テンプレートの Google スプレッドシートに値を写すか、
`URLから読込` で共有済みのシートを直接読みます（読めるのは
`https://docs.google.com/spreadsheets/d/…` で「リンクを知っている全員」に
共有されたこのテンプレートのシートだけです）。

**既知の制限** — 5 形式のなかで最も情報が落ちます。理由は 3 つです。

- **固定の枠**。資質 10・呪文 20・覚醒者パワー 20・インプラント 30・機器 7・
  コネ 20・知識技能 25 まで。
- **選択肢が本より短い**。メタタイプ 5・魔法使いの種別 6・インプラントの等級
  5・作成方式 2 のみ。
- **装備がすべて 1 つの自由記入欄を共有**。本の複数のリストに同じ名前がある品目は、
  読み直しで先に試したリストの側に入ります（装備として持っていた手榴弾が武器に
  なって戻る、など）。

溢れた分・丸められた分は、書き出し前の確認に件数と品目名で出ます。

呪文と複合体で選んだもの（Increase [Attribute] の能力値、Detect [Life Form] の
対象など）は、名前の後ろに括弧で書きます（`[能力値] 増強/インクリース・ [アトリビュート]（筋力）`）。
アデプトパワーと同じ書き方で、読込でも括弧を外して読み戻します。手で書くときは
`[能力値] 増強（筋力）` のように短い名前でも読めます。

**A.I. のプログラムは書きません。** テンプレートに欄がなく、装備や複合体の欄に
書くと読み直しでそちらとして買われてしまうためです。確認には「A.I. のプログラム」が
失われると出ます。

## FVTT書出（Foundry VTT / shadowrun5e）

**対象** — Foundry VTT v13 ＋ shadowrun5e システム **0.34.5**。
日本語化 Mod shadowrun5eja 3.1 と併用できます（文言だけなのでデータ形式には
関与しません）。0.37.x は「通れば良い」の参考扱いです。

**何が出るか** — Foundry のアクター JSON **ではなく**、システム内蔵の
Chummer 取り込み機能が読む形（Chummer の *File > Export > JSON* 相当）です。
アクターの組み立てはシステム側に任せます。技能セットの扱い・コンペンディウム照合・
データモデルがシステム側のままになるので、そのほうが壊れません。

中身は本体・技能・資質・コンタクト・ライフスタイル・呪文・アデプトパワー・複合体・
防具・サイバーウェア／バイオウェア・装備・武器・ヴィークルとドローン
（搭載改造・積載物・マウントの銃まで）・ポートレートです。

**取り込み手順** — Foundry のアクター一覧から **Chummer/Data Import** を開き、
書き出した JSON を渡します。

**既知の制限**

- **メタタイプ固有の生得パワー**は品目になりません（書き出し前の確認に出ます）。
- **A.I. のプログラム**も書きません。システムの Chummer 取り込みが `aiprograms` を
  読まないためです（スキーマに型はあるが、品目にする処理がない）。確認に 1 件ずつ出ます。
- 品目は `sourceid`（GUID）→ 名前 → 英語名 の順でワールドのコンペンディウムを
  引きます。該当がなければ空の品目を作ってこちらのフィールドで埋めるので、
  コンペンディウムを入れておくほど結果が良くなります。
- `.chum5`（保存形式）は Foundry 側では読めません。完成値が必要な形式です。

## ココフォリア

**何が出るか** — コマ 1 体分の JSON を**クリップボードにコピー**します。
テストは BCDice の `ShadowRun5`（`9B6@3` のような確定値の記法）。

**取り込み手順** — ココフォリアの卓で**そのまま貼り付け**ます。

**関連ボタン**

- `チャットパレット` — パレット（コマンド一覧）だけをテキストでコピー。
- `精霊コマ` — 束縛済み精霊／登録スプライトを、それぞれ別のコマとして JSON 配列で
  コピー。該当がいないときはボタン自体が出ません。
- `未修得技能も` — オンにすると、未修得技能（能力値−1 で代用できるもの）と
  取得済みの知識技能もパレットに出します。ココフォリアとユドナリウムの両方に効きます。

**既知の制限** — パレットは**確定値**です。卓で修正値をいじる前提なら
ユドナリウムのほうが向きます。ポートレートは運べません。

A.I. のプログラムは振るものがないので、コマのメモに 1 行で出します。

## ユドナリウム

**何が出るか** — キャラクターコマ 1 体分の `.zip`。中身は `data.xml` と
ポートレート画像です。ダイスは BCDice の `ShadowRun5`。

**取り込み手順** — zip を**卓にドラッグ＆ドロップ**するか、「ZIP読込」から渡します。

> `.xml` 単体ではなく zip なのは、入り口 2 つの両方を通るのがこれだけだからです。
> ドラッグ＆ドロップは裸の xml も読みますが、「ZIP読込」のファイル入力は渡された
> ものを必ず unzip しようとして `End of central directory not found` で落ちます
> （`accept` に `application/xml` を挙げているにもかかわらず）。udonarium.app
> 1.17.4 で確認。

**パレットは変数方式との併用です。** 能力値・武器・魔法・マトリックスは
`//敏捷力=5` で変数を定義して `({敏捷力}+{射撃技能A})B6@{射撃精度A}` のように
参照するので、**卓で修正値をいじれます**。技能一覧や細かいテストは確定値で展開します。

A.I. のプログラムは振るものがないので、パレットの末尾に一覧として出します。

コマの `detail` にはプレイ中に押すものだけ置いています（コンディション・モニター、
エッジ、そのターンの残り移動力）。キャラクターの内容はパレットの変数が持っているので
重複させていません。

**`ユドナリウム（お供のコマ）`** — 束縛した精霊・登録したスプライト・ヴィークル・
ドローンを 1 体 1 コマで書き出します。**種類ごとに別の zip**（精霊／ヴィークル／
ドローン）で、ユドナリウムは zip の中の xml を全部読むのでまとめて卓に出ます。
該当がないときはボタン自体が出ません。

## 書き出し以外でキャラクターが外に出る経路

- **共有リンク**（`共有リンクをコピー`）— 読み取り専用。キャラクターは URL の
  フラグメントに埋め込まれ、サーバーには保存されません。ポートレートは含みません。
  形式は [`share-link.md`](share-link.md) にあります。
- **印刷 / PDF** — 印刷用レイアウトに切り替えて印刷します。ブラウザのダイアログで
  「PDF として保存」も選べます。

## 読み込める形式（参考）

書き出しの裏返しとして、`読込` が受け付けるのは次の 4 種類だけです。
一般の Excel ブックや他の JSON は読めません。

1. このアプリで書き出した JSON
2. Foundry VTT（shadowrun5e）のアクターを Export Data した JSON
3. Chummer5a の `.chum5` / `.chum5lz`
4. ［SR5］キャラシテンプレートを `.xlsx` で書き出したもの
