  - Chummer は開くときに `<bonus>` を実行し直さないので、書き出しに改善効果が無い効果は Chummer で効かない。
    資質が付けるクリッター・パワーの改善効果は書くようになった（[往復確認](fixtures/critter-powers/README.md)）。
  - 資質そのものの効果は、Dead SIN の装備以外は書く。テスト用セーブ 34 件で Chummer が保存した
    342 件中 323 件を再現する（`scripts/chum5_reconcile.py --improvements` が種類別に出す）。
    残りの 19 件は、古い Chummer のデータの名残や取り込み側の制限で、書き出しでは再現できない。
  - ウェアの改善効果も書く（レーティングで変わる値は、そのレーティングで計算する）。テスト用セーブで
    サイバーウェア 85 件中 51 件、バイオウェア 113 件中 112 件を再現する。残りは古い Chummer のデータの名残。
  - アデプトパワーと導師精霊の改善効果も書く。テスト用セーブでパワー 75 件中 70 件、導師精霊 51 件中 37 件。
    パワーの効果は、Chummer と同じく買ったレベルと無料のレベルの合計（`TotalRating`）で書く。
    パワーの残り 5 件は古いデータの名残（効果の無くなった Linguistics が 4 件、
    今は ThrowRangeSTR になった Precision Throwing の ThrowRange が 1 件）。
    導師精霊の残りのうち 12 件は、2019 年より前の Chummer が導師精霊の印として作った Mentor's Mask の
    パワーポイントとドレイン（6 セーブ）。取り込みで資質 Mentor's Mask に置き換え、資質の改善効果として書く。
  - 格闘技スタイルの改善効果も書く（専門化の選択肢）。テスト用セーブで 1 件中 1 件。
    設定「格闘技スタイルの専門化を無料にする」で取った専門化は、無料にしてスタイルに結び付けて書く。
    Chummer がこの設定で自動で足す専門化は費用を取る（`free=False`）ので、そこは真似しない。
    無料レベルを受けるパワーを買っていなければ、Chummer と同じくレーティング 0 のパワーの行を足す
    （テスト用セーブの 7 件すべてで、改善効果から来る行が一致）。
  - アーマーとアーマーの改造の改善効果も書く（着ていないアーマーの分は無効として書く）。テスト用セーブで
    95 件中 61 件。残りは保存に行のない古い限界値の修正と、今のデータに効果のない YNT Softweave Armor。
  - 装備の改善効果も書く（アーマーに入れた装備は、アーマーを着ていなければ無効として書く）。テスト用セーブで
    208 件中 183 件。残りは保存に行のない古い限界値の修正、古い版の Weapon Focus、
    取り込めない品目と、5.202 の Chummer が乗り物に後から積んだ装備にも作っていた改善効果（Serpent の 2 件）。
  - 乗り物の装備は、乗り物に最初から付いてくるもの（Caduceus の Medkit、ドローンのオートソフトなど）だけ書く。
    今の Chummer は後から積んだ装備に改善効果を作らない（`PurchaseVehicleGear` が `blnAddImprovements: false`）。
  - 結んだフォーカスの改善効果も書く（Weapon Focus の武器、Power Focus、Spellcasting Focus、Qi Focus の

- [ ] **キャリアで消した品目・下げた値のカルマ**
  - 調査済み・未実装（2026-10-27）。直し方はまだ決めていない。
  - Chummer はキャリアで品目を消してもカルマを返さない。削除は `CharacterShared.RemoveSelectedObject` が品目の
    `RemoveAsync` を呼ぶだけで、呪文・複合体・イニシエーションの段・格闘技のクラスにも、消すときにカルマを動かす処理は無い。
    能力値・技能はキャリアで下げる操作が無い。カルマが戻るのは、支出記録の「元に戻す」（`ExpenseUndo`）だけ。
  - このアプリは、カルマを持ち物から毎回計算し直す。資質（`_career_qualities.py`）以外は、作成時から持っていた
    品目を消すと、作成時に払ったカルマが戻る。精霊・スプライトの基準点（`item_ids`）は、キャリアで呼んだものに
    奉仕のカルマを取らないためのもので、作成時からのものを消せば戻る。
    作成時のキャラクターをキャリアに移し、1 つ消して残りカルマを比べた結果：

    | 消したもの | 戻ったカルマ |
    | --- | --- |
    | 無料枠を超えた呪文 1 つ | 5 |
    | 無料枠を超えた複合体 1 つ | 4 |
    | A.I. のプログラム（Browse） | 5 |
    | 格闘技のスタイル（Karate、技法 2） | 12 |
    | 格闘技の技法 1 つ | 5 |
    | イニシエーション 1 段（`initiate_grade` 1→0） | 13 |
    | サブマージョン 1 段 | 13 |
    | Weapon Focus フォース 2 | 6 |
    | 精霊の奉仕 2（Hermetic） | 2 |
    | スプライトの奉仕 2 | 2 |
    | 無料の点を超えたコンタクト | 7 |
    | 作成時にカルマで買った LOG の 1 段 | 10 |
    | 作成時にカルマで買った技能の 1 段 | 4 |

  - キャリアで買ってから消した場合は、Chummer の「元に戻す」と同じく戻るので、違いは作成時からの品目だけ。
    画面で基準点を見て削除を区別しているのは資質タブだけ。
  - もう 1 つの違い：キャリアで足したコンタクトに、無料の点を超えた分のカルマを取る（上の例で 7）。
    Chummer の `AddContact` はカルマも支出記録も作らない。コンタクトの点は作成時だけのもの（`contacts.py` の
    超過の値段はキャリアかどうかを見ていない）。
  - テスト用セーブ（キャリア 7 件）を読み込んで同じことをすると、読み込んだ時点が基準点になるので、
    戻る量は品目と保存のされ方で変わる（Draught の呪文は 5、ほかの 3 件は 0。コンタクトは 3〜6）。
  - 決めること：作成時からの品目を消したとき、資質と同じく戻さないか（基準点に品目の id と値段を持つ）。
    今の「消せば戻る」を、作成時のやり直しとして残すか。規模の目安：戻さないなら中（品目の種類ごとに基準点と内訳が要る）。
